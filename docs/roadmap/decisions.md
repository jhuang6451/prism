新增一条，不删除历史。

## ADR-0001 产品定位：单用户远程访问优先

- 状态：已接受
- 日期：2026-10-27
- 关联：[产品文档](01-product.md)

### 背景
远程桌面有"多用户并行"（Wolf）和"单用户远程访问"（RDP）两类目标。Sunshine 面向后者，但只能复制
已登录的本地桌面，远程使用依赖本地显示器和本地登录。

### 决策
Prism 优先实现单用户远程访问的 RDP 模型：登录前可用、远程会话独立于物理座位、断开保留。多用户
并行列为远期目标（M6），当前设计不得阻碍它（会话按用户划分，不假设全局只有一个用户）。

### 后果
- 需要系统级组件和会话管理（ADR-0002、ADR-0003）。
- 多用户的端口复用、设备隔离等问题推迟。

## ADR-0002 Prism 作为系统级服务：prismd + 会话代理

- 状态：已接受（方向）；helper 与 PAM 细节待 S3
- 日期：2026-10-27
- 关联：Q7、Q11、M3

### 背景
用户级服务挂在 `graphical-session.target` 上，本地不登录就不运行。开启 linger 可以绕过，但不能创建
真正的登录会话，也无法支持多用户。

### 决策
- `prismd` 以专用系统用户 `prism` 运行，负责网络面（配对、应用列表、启动、Web UI）、认证和会话代理器。
- 特权操作（打开 PAM 会话、在 `user@UID` 中启动单元）由接口极小的 root 辅助进程完成。
- 采集、编码、音频、输入、启动应用由以用户身份运行在会话内的会话代理完成。
- 已配对设备须绑定到 Linux 用户才能建立会话；可选 PIN 或系统密码。

### 备选方案
- **linger + 用户级服务**：成本最低，但不是真正的登录会话，无法多用户；只作为 M2 的过渡验证手段，M3 后不再保留（ADR-0009）。
- **prismd 以 root 运行全部功能**：攻击面过大，且以 root 访问用户的 PipeWire 和 Wayland 很别扭。

### 后果
- 需要 IPC、迁移、系统级打包（M3）。
- 与 Windows 版 Sunshine、GNOME 远程登录的结构一致，便于参考。

### helper 与 PAM 细化（提议，证据来自 S3 的 VM 部分和 S1 真机，2026-11-02）
S3 已在 VM 中证实 root 服务通过 PAM 能开出 `Type=wayland`、`Class=user`、无座位、`Remote=yes` 的会话，并在其中运行
嵌套 Plasma，注销后无残留。由此对 helper 提出以下设计约束，待 T3.3 实现时定稿：

| 约束 | 证据 | 建议 |
|---|---|---|
| SELinux 域 | S3 F2：helper 在 `unconfined_service_t` 下保留 `pam_selinux` 时，`exec` 用户进程得到 `EACCES` | 二选一并写入 T3.3：给 helper 一个能转换到用户域的受限域并保留 `pam_selinux`；或明确接受会话运行在 helper 的域 |
| 环境导入 | S3 F3：用户管理器不会自动带上 `XDG_RUNTIME_DIR`、`XDG_SESSION_ID`、`XDG_SESSION_TYPE` | helper 或会话目标启动前显式 `set-environment` |
| 就绪等待 | S3 F4、F5：`pam_open_session` 返回时 `user@UID` 未就绪；用户管理器失败时会话仍显示 Active | 等待用户总线和 `is-system-running`，带总超时；以用户管理器状态而非会话状态判断成功 |
| 设备授权 | S3 F1、S1 F9/R3/R7/R9/R15：`uaccess` 不授权给无座位会话；涉及 `card*`、`uinput`、`uhid`、passthrough 键鼠、Prism 生成的虚拟手柄节点；手动 ACL 会被 `uaccess` 重置 | 用户组或属主类 udev 规则，由系统级安装提供（T2.10、T3.6）；授权失败时输入必须失败关闭，不能落到本地座位（见架构第 6 节） |
| polkit 与密钥库 | S3 Q6、S1 R8：无座位会话的网络、挂载、关机为 `auth_admin`；没有密码时 `pam_kwallet5` 不解锁 | T3.8 的受限 polkit 规则；PIN 认证时钱包不自动解锁，写入文档 |
| 未覆盖 | S3 暂缓（2026-11-02） | NVIDIA 设备与 NVENC、真实声卡与 WirePlumber、`systemd-homed`、带密码登录时的 KWallet，并入 T3.3 的验收 |

## ADR-0003 一个用户一个图形会话：有则接入，无则新建

- 状态：已接受
- 日期：2026-10-27
- 关联：Q5、Q14、T2.2、T2.7

### 背景
Linux 上一个用户只有一个 systemd 用户管理器和一个会话总线，桌面环境普遍不支持同一用户同时运行两个
图形会话。RDP 的做法是远程登录时强制注销本地会话，对工作连续性不友好。

### 决策
- 用户有本地会话时，远程接入该会话，以虚拟屏幕的形式出现（现有 Desktop (Virtual) 能力）。
- 用户没有会话时，新建远程会话；有断开的远程会话时接入它。
- 提供"注销本地、远程重开"作为可选操作。

### 备选方案
- **强制注销本地（RDP 方式）**：打断工作，否决。
- **同一用户并行两个桌面 + 私有 D-Bus 隔离**：Plasma 等桌面不支持，配置文件互写，否决；私有 D-Bus
  只保留给过渡期的隔离 headless 应用模式。

### 后果
- 远程会话存在时本地登录仍是冲突点，由 M4 处理（ADR 待 S4 后补充）。

## ADR-0004 远程会话运行完整桌面环境，放弃手工拼装外壳

- 状态：已接受
- 日期：2026-10-27
- 关联：P2、T2.3

### 背景
早先的方案是在 headless labwc 上用 autostart 拼装面板、启动器、通知、polkit 代理等。

### 决策
远程会话运行完整的桌面环境（默认 Plasma），`labwc-minimal` 作为兜底选项。

### 后果
- 面板、启动器、文件对话框、通知、输入法、polkit 代理全部由桌面环境提供。
- 需要解决桌面环境在 headless 或嵌套模式下的运行问题（ADR-0005）。

## ADR-0005 远程会话的合成结构

- 状态：已接受（2026-11-02，用户确认）
- 日期：2026-10-27
- 关联：Q1–Q4、S1、S2、T2.3a、T2.3b

### 背景
完整桌面需要一个合成器；Prism 需要采集它的输出并注入输入。

### 候选
- **嵌套**：外层 `prism-labwc`（headless 输出、screencopy、虚拟输入、HDR 补丁）+ 内层完整桌面作为
  外层的 Wayland 客户端。参考 Wolf（gst-wayland-display + sway/gamescope/XFCE）。
- **直连 KWin headless**：`kwin_wayland --virtual`，采集用现有 `kwingrab.cpp`，输入走 EIS 或 fake input。

### 当前倾向
嵌套：采集、输入、HDR 只实现一次，桌面环境无关。最终以 S1/S2 的延迟、HDR、输入数据为准。

### 决策（2026-11-02）
采用**嵌套**：外层 `prism-labwc` + 内层完整桌面（默认 Plasma），内层使用用户真实的会话总线（ADR-0006）。

### 依据（S1、S2 的 VM 与真机数据）
- 当初的理由"HDR 只实现一次"没有成立：内层 KWin 的嵌套后端和 `--virtual` 后端都不报 HDR 能力（S1 R16、S2 R1）。
  选嵌套的理由改为：
  - **外层是可控的 HDR 与游戏旁路**：直接跑在外层的客户端有 HDR（S1 R16-B），用外层原生的指针约束和输出刷新率，
    不经过 KWin 嵌套后端。Steam 大屏幕走这条旁路，见 ADR-0008。
  - **分发可控**：`prism-labwc` 是固定提交的 labwc + 静态 wlroots 加两个小补丁，与用户的桌面版本无关；直连 KWin 要补的
    HDR（虚拟输出能力、ScreenCast 的 10 位格式与色彩信息）只能走 KWin 上游，补过的 `kwin_wayland` 无法随 Prism 分发
    （与系统 Plasma 的 ABI 绑定），见 `spikes/S2-direct-kwin-headless.md` 的"KWin 源码核查"。
  - **输入复用**：现有输入桥直接可用；直连需要新写 EIS 转发桥。
  - **桌面环境无关**：`labwc-minimal`、`custom` 内层可用同一套采集和输入。
- 性能不是决定因素：直连 KWin 也要合成两次（虚拟输出自身 + ScreenCast 重新渲染场景），嵌套约三次，都是全屏贴图量级；
  真机上外层合成器的显存约 21 MiB（S1 R13）。

### 已知缺陷与处理
| 缺陷 | 来源 | 处理 |
|---|---|---|
| 内层桌面 HDR 不可用 | S1 R16 | 游戏和 HDR 内容走外层旁路；内层 HDR 只作为向 KWin 上游贡献的嵌套后端补丁处理，排在主干之后 |
| 内层 KWin 输出固定报 60Hz | S1 R8 | 桌面场景先接受；实际帧率与修复方向留到 M5 |
| 内层客户端的指针锁定不转发到外层（需手动按右 Ctrl） | S1 R10 | 游戏走外层旁路，不受影响；内层的处理留到 M5 |
| 外层连接出错时内层 KWin 直接 abort | S1 R14 | T2.3b 调查并定义恢复行为（Q18） |
| 内层 KWin 的尺寸与全屏参数要靠 PATH 垫片传入 | S1 F1、R8 | T2.3a 给出稳定的传参方式 |

### 备选方案
- **直连 KWin headless**（`kwin_wayland --virtual`）：结构上没有 R8、R10、R14，但 HDR 依赖 KWin 上游补丁、输入要新写
  EIS 桥、只适用于 KDE。保留为将来 KWin 上游具备 headless HDR 时的再评估对象。

## ADR-0006 私有 D-Bus 只用于隔离 headless 应用模式

- 状态：已接受
- 日期：2026-10-27
- 关联：P3、ADR-0003

### 背景
文件对话框弹到物理屏幕的原因是 headless 会话共用本地会话的 D-Bus 和 portal。

### 决策
远程会话是用户唯一的会话，使用用户真实的会话总线，由桌面环境按常规导入环境；不引入私有总线。
过渡期保留的隔离 headless 应用模式如需修复对话框问题，才使用 `dbus-run-session` 式的私有总线。

## ADR-0007 客户端"退出"的语义

- 状态：已接受（2026-11-02，用户确认）
- 日期：2026-10-27
- 关联：Q10、S5、T2.4

### 当前倾向
`session` 模式下，客户端"退出"默认等于断开（会话保留），可配置为同时注销；应用退出不影响会话。
需要 S5 确认原版 Moonlight 和 Iris 在这种语义下的表现。

### 决策（2026-11-02）
- `session` 模式下，`cancel`（客户端"退出"）默认只结束串流并让当前附着的入口变为空闲，**不结束会话**；可配置为同时注销。
- 应用退出不影响会话。
- `running()` 对 `session` 模式解释为"当前有入口附着在串流上"：`cancel` 后返回 0，`serverinfo` 显示 FREE，客户端可以
  `launch` 另一个入口，由服务端按策略接入同一会话。原则上不需要修改客户端。
- 依据是 S5 的服务端分析。客户端行为（提示文案、退出后立即启动另一入口、断网重连走 `resume` 还是 `launch`）
  不再单独实验，并入 T2.4 的验收（原版 Moonlight 与 Iris 都要测）。若客户端表现与预期不符，回到本 ADR 修订。
- 安全约束（S5）：M3 起 `launch` 和 `resume` 都必须校验设备绑定的用户与会话所属用户一致（T3.4）。

## ADR-0008 Steam 大屏幕的形态

- 状态：提议
- 日期：2026-10-27
- 关联：Q9、S6、T2.6

### 当前倾向（2026-11-02 用户修订）
Steam 大屏幕走**外层旁路**：在用户的远程会话里，`steam -gamepadui` 作为外层 `prism-labwc` 的客户端运行，与内层
Plasma 并列，属于同一个 logind 会话、使用同一条用户会话总线。这样 Steam 大屏幕和 Plasma 桌面一样经过完整的用户登录
（PAM 会话），由 Prism 的会话管理统一新建、接入、断开和注销；游戏直接跑在外层上，能用外层的 HDR、指针约束和刷新率，
绕开 KWin 嵌套后端的缺陷（ADR-0005）。

不采用的形态：
- **作为内层 Plasma 里的应用**：HDR 拿不到，指针锁定和刷新率受嵌套后端限制（S1 R8、R10、R16）。
- **现有 Steam Headless**（按应用启停的独立 labwc + Steam，挂在本地会话的用户管理器下）：不是用户的登录会话，不能
  远程独立管理会话，不符合产品目标。过渡期保留，旁路稳定后再决定去留。

以 S6（已按旁路调整范围）的结果为准，ADR 仍为"提议"。

## ADR-0009 M3 之后只保留系统级部署

- 状态：已接受（2026-11-02，用户确认）
- 日期：2026-11-02
- 关联：ADR-0002、T3.5、T3.6、Q12

### 背景
原计划在 M3 引入系统级服务后，继续维护现有的用户级安装（`prism.service` 用户单元、
`PartOf=graphical-session.target`）。两种部署并存意味着两套单元、两套配置位置和两条测试路径。

### 决策
Prism 升级后全面转向系统级服务（`prismd` + helper + 会话代理）。M3 完成后不再提供独立的用户级部署：
- 现有用户级安装通过迁移命令（T3.5）一次性迁移到系统级，迁移后移除用户级单元，不保留并行运行的用户级模式。
- 接入本地会话（Desktop (Virtual)、Mirror、portal）仍由会话代理在本地会话里完成，功能不变，只是由 `prismd` 统一调度。
- M2 期间仍是用户级服务，用于验证会话模型；为 M2 做的用户级专用改动（例如无图形会话时启动，T2.11）不作为长期能力维护。

### 后果
- T3.6 不再要求"用户级模式继续可用"；`install.sh`、`prism --update`、`prism --remove` 只需支持系统模式和一次性迁移。
- 系统级安装需要 root，这成为使用 Prism 的前提，需要在 README 写明。
- 测试矩阵减少一条路径（05 的 4.8）。
