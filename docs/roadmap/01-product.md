# 01 产品定位与说明

## 1. 背景

远程桌面有两类不同的目标：

| 目标 | 典型场景 | 代表项目 |
|---|---|---|
| **多用户并行** | 我在电脑前码字，家人在客厅用独立的会话玩游戏、看电影，互不干扰。 | Wolf（Games on Whales） |
| **单用户远程访问** | 我人不在电脑前，也要能用自己的电脑：办公、开 Steam 大屏幕玩游戏，用完注销。 | Windows RDP、GNOME 远程登录 |

Sunshine 面向第二类，但它本质上是"远程显示复制器"：必须先在接了显示器的电脑上登录、打开桌面
环境、启动 Sunshine，远程才能看到这块已有的屏幕。远程使用依赖本地真实显示器所连接的桌面。

Prism 已经在 Sunshine 之上加了按应用选择的捕获模式（镜像、虚拟屏幕、headless labwc），但仍然
没有脱离这个模型：

- `prism.service` 是用户级服务，`PartOf=graphical-session.target`，本地不登录就不运行。
- headless 会话随单个应用启停，没有桌面外壳，并继承本地 KDE 会话的 D-Bus 总线和
  `XDG_CURRENT_DESKTOP`。结果是在 headless 里打开的应用，文件选择对话框弹到物理显示器上。

## 2. 产品定位

**Prism 是 Linux 上基于 Moonlight 协议的远程桌面主机。只要主机开着，就能从任何 Moonlight/Iris
客户端登录到自己的完整桌面或游戏模式；与本地是否登录、是否接显示器无关；断开后会话保留，回来
接着用。**

优先服务单用户远程访问（RDP 模型）。多用户并行（Wolf 模型）是远期目标，现在的架构设计不能
把它堵死。

## 3. 目标与非目标

### 目标

| 编号 | 目标 |
|---|---|
| G1 | **登录前可用。** 主机开机后无需任何本地操作即可被远程连接和登录，包括完全无头的主机。 |
| G2 | **完整桌面。** 远程会话里有完整的桌面环境（面板、启动器、文件管理器、通知、文件对话框、输入法），而不是空白的合成器。 |
| G3 | **会话持续。** 断开不等于注销；重连回到原样。只有用户显式注销或超时才结束会话。 |
| G4 | **不打断本地工作。** 本地已登录时，远程接入同一个会话，相当于插上一块新屏幕；不强制注销本地会话。用户也可以主动选择"注销本地、远程重开"。 |
| G5 | **应用联动。** 同步的应用在当前会话里打开；应用之间的文件对话框、链接打开、通知都落在用户正在看的那个会话里。 |
| G6 | **游戏体验不退步。** 现有的 HDR、低延迟、手柄（含 DualSense/Edge）、Steam 能力在新模型下保持。 |

### 非目标（当前阶段）

- **多用户同时并行串流。** 列入 M6；之前只保证"一个用户的会话结构"不阻碍以后扩展。
- **非 Linux 平台的新功能。** 上游的 Windows/macOS 代码继续可编译，但新能力只做 Linux。
- **非 systemd 主机。** 依赖 logind 和 systemd 用户管理器。
- **更换协议。** 继续使用 Moonlight 协议，不实现 RDP/VNC。
- **远程协助**（把自己的屏幕共享给别人看）。
- **X11 桌面会话。** 远程会话只支持 Wayland 桌面；X11 应用通过 Xwayland 运行。

## 4. 用户场景

| 编号 | 场景 | 期望行为 |
|---|---|---|
| U1 | 出门在外，用平板连回家里的电脑办公；电脑开着但没人登录。 | 选择 "Desktop"，验证身份后进入自己的完整 Plasma 桌面。文件对话框、通知都在这块远程屏幕上。 |
| U2 | 主机放在柜子里，没接显示器；在客厅电视上玩 Steam 大屏幕。 | 选择 "Steam Big Picture"，直接进入大屏幕模式；HDR、手柄正常。 |
| U3 | 在书房电脑前工作，起身去客厅继续。 | 本地会话已登录，远程接入同一会话，客厅电视成为它的一块新屏幕，窗口可以拖过去。本地屏幕的处理方式可配置。 |
| U4 | 远程会话还在（之前断开过），用户回到电脑前想本地登录。 | 有明确的处理策略：提示用户、或结束远程会话、或拒绝本地登录，不允许出现两个互相冲突的桌面。 |
| U5 | 网络断了，几分钟后重连。 | 回到原样，所有窗口、未保存的工作都还在。 |
| U6 | 在客户端应用列表里点 Firefox。 | 有会话就在会话里打开 Firefox 并切到前台；没有就先建会话再打开。 |
| U7 | 远程用完，想彻底结束。 | 在桌面里注销，或在 Web UI 里结束会话；会话里的应用全部退出，资源回收干净。 |
| U8 | 主机重启后。 | 无需登录本地，远程即可再次连接（会话本身不跨重启保留）。 |

## 5. 核心概念与对外行为

### 5.1 一个用户，一个图形会话

Linux 上一个用户只有一个 systemd 用户管理器和一个会话 D-Bus 总线，桌面环境普遍不支持同一用户
同时运行两个图形会话。Prism 因此遵守一条规则：**同一用户同一时刻只有一个图形会话。**

| 当前情况 | 选择 "Desktop" 时的行为 |
|---|---|
| 用户有本地会话 | **接入**：在本地会话里加一块按客户端分辨率创建的虚拟屏幕（现有 Desktop (Virtual) 能力）。 |
| 用户有已断开的远程会话 | **接入**：重新连上这个远程会话。 |
| 用户没有任何会话 | **新建**：创建远程会话（外层 headless 合成器 + 内层完整桌面）。 |
| 本地已登录，且用户选择"注销本地、远程重开" | 结束本地会话后**新建**远程会话。 |

### 5.2 客户端应用列表

| 条目 | 行为 |
|---|---|
| **Desktop** | 按 5.1 接入或新建。主入口。 |
| **Steam Big Picture** | 在当前会话里以大屏幕模式启动 Steam（没有会话就先新建）。具体形态待 S6 实验决定，见问题 Q9。 |
| **同步的应用**（app-sync） | 在当前会话里启动并切到前台；没有会话就先新建。 |
| **Desktop (Mirror)** | 兼容模式：镜像本地物理屏幕，与 Sunshine 行为一致。 |
| 旧的隔离 headless 应用 | 过渡期保留（每个应用一个独立 labwc），新路径稳定后再决定去留。 |

### 5.3 生命周期语义

| 动作 | 结果 |
|---|---|
| 客户端"退出"（Quit） | 默认**断开**：串流结束，会话保留。可配置为同时注销。最终语义待 S5 决定（ADR-0007）。 |
| 客户端掉线 | 断开，会话保留。 |
| 会话里打开的应用退出 | 不影响会话。 |
| 用户在桌面里注销 | 会话结束，串流随之结束。 |
| Web UI "结束会话" | 会话结束。 |
| 断开后超过空闲超时 | 会话结束（超时可配置，默认不超时，待定）。 |
| 主机关机或重启 | 会话结束；开机后仍可远程登录新会话。 |

### 5.4 身份与认证

- 配对证明的是"这台设备可信"，不是"这台设备属于哪个 Linux 用户"。
- 管理员在 Web UI 里把每台已配对设备绑定到一个 Linux 用户。未绑定的设备不能新建会话。
- 新建会话时可以要求额外输入 PIN 或系统密码（可配置）；接入已有会话是否需要再次验证也可配置。
- 远程会话在桌面内锁屏后，用户可以在串流画面里输入密码解锁。

### 5.5 本地屏幕（接入模式）

本地已登录时远程接入，本地物理屏幕有三种处理方式，由配置项决定：

1. 保持点亮（适合"同一个人在两处看"）。
2. 关闭物理输出（现有 Desktop (Virtual) 的行为，适合隐私）。
3. 关闭物理输出并在断开时锁屏。

### 5.6 用户可见的保证

- 远程会话里的文件对话框、通知、`xdg-open` 打开的链接、单实例应用的激活，都出现在远程会话里。
- 远程会话的音频只进串流，不从主机扬声器播放；接入本地会话时按现有镜像/虚拟模式的规则处理。
- 失败时明确报错，不会悄悄退回到捕获别的屏幕或别的会话。

## 6. 兼容与迁移

- 现有捕获模式（`default`、`virtual`、`headless`、`portal:<output>`）和 `apps.json` 格式继续有效。
- 现有用户级安装方式在 M3 之前保持可用；M3 引入系统级安装后提供迁移命令，保留配对、凭据、
  应用配置和 HDR 校准数据。
- 上游 Sunshine 的同步不受影响：新代码放在独立模块里，对上游文件的改动保持最小，见
  [架构文档](02-architecture.md#9-上游同步策略)。

## 7. 产品层面的成功标准

| 编号 | 标准 |
|---|---|
| A1 | 主机重启后不做任何本地操作，客户端能在 30 秒内（从点 "Desktop" 算起，含认证）看到完整桌面。 |
| A2 | 远程会话里用任意应用打开文件对话框，对话框 100% 出现在远程画面中。 |
| A3 | 断开再重连，窗口和未保存内容保持不变。 |
| A4 | 本地已登录时远程接入，本地会话不被注销，应用不被重启。 |
| A5 | 远程会话里的游戏延迟和 HDR 表现不差于当前 Steam Headless（以 M0 基线为准）。 |
| A6 | 注销后没有残留的进程、单元、音频设备和状态文件。 |
